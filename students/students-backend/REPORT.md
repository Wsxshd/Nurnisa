# Отчет по курсовому проекту: «Учет студентов и оценок»

## 1. Цель и стек
Серверное приложение (REST API) для учета студентов, групп, преподавателей, предметов и оценок.
Стек: Java 17, Spring Boot 3.2 (Web, Data JPA, Validation), PostgreSQL 16, Maven, Docker.

## 2. Архитектура (слои)
Запрос проходит цепочку: **Controller → Service → Repository → PostgreSQL**.
- **Controller** - принимает HTTP-запрос, проверяет входные данные (`@Valid`), возвращает JSON.
- **Service** - бизнес-логика (поиск связанных записей, 404, если не найдено).
- **Repository** - интерфейсы Spring Data JPA; SQL для простых операций генерируется автоматически,
  отчеты написаны на JPQL.
- **Model** - JPA-сущности, отображение классов на таблицы.
- **DTO** - объекты для входящих запросов (с правилами валидации) и результатов отчетов.
- **GlobalExceptionHandler** - единая обработка ошибок (400, 404, 409) в формате JSON.

## 3. База данных (5 таблиц)
| Таблица | Назначение | Связи |
|---|---|---|
| `study_groups` | учебные группы | 1 группа - много студентов |
| `students` | студенты | FK `group_id` → `study_groups` |
| `teachers` | преподаватели | 1 преподаватель - много предметов |
| `subjects` | предметы | FK `teacher_id` → `teachers` |
| `grades` | оценки | FK `student_id` → `students`, FK `subject_id` → `subjects` |

`grades` реализует связь «многие ко многим» между студентами и предметами.

**Нормализация до 3NF:**
- 1NF: все поля атомарны (имя и фамилия раздельно, нет повторяющихся групп).
- 2NF: у всех таблиц простой первичный ключ `id`, частичных зависимостей нет.
- 3NF: нет транзитивных зависимостей. Название группы хранится только в `study_groups`
  (в `students` - лишь `group_id`), ФИО преподавателя - только в `teachers`
  (в `subjects` - лишь `teacher_id`). Каждый неключевой атрибут зависит только от ключа своей таблицы.

**Целостность:** внешние ключи, `UNIQUE` (email, название группы/предмета), `CHECK` (оценка 1..5, часы > 0),
индексы по внешним ключам. При удалении студента или предмета его оценки удаляются каскадно
(`ON DELETE CASCADE`); группу или преподавателя со связанными записями удалить нельзя (ошибка 409).

## 4. CRUD
Полный CRUD (создание, чтение, изменение, удаление) реализован для всех пяти сущностей:
`/api/students`, `/api/groups`, `/api/teachers`, `/api/subjects`, `/api/grades`.
Методы: GET (список и по id), POST (создать, 201), PUT (изменить), DELETE (удалить, 204).

## 5. Поиск и отчеты
**Поиск:** `GET /api/students?search=иван` - по части имени или фамилии без учета регистра.
Также фильтр оценок: `GET /api/grades?studentId=1&subjectId=2`.

**Отчеты (JOIN + агрегатные функции), JPQL в `GradeRepository`:**
1. `/api/reports/students-average` - JOIN grades+students+groups, `AVG`, `COUNT`, сортировка по среднему баллу.
2. `/api/reports/subjects-stats` - JOIN grades+subjects+teachers, `AVG`, `MIN`, `MAX`, `COUNT` по предметам.
3. `/api/reports/groups-stats` - JOIN grades+students+groups, `AVG`, `COUNT(DISTINCT)` по группам.

## 6. Валидация
Аннотации Bean Validation в DTO и сущностях: `@NotBlank`, `@Email`, `@Size`, `@Min/@Max` (оценка 1..5),
`@Past` (дата рождения), `@PastOrPresent` (дата оценки), `@NotNull` (внешние ключи).
При ошибке возвращается HTTP 400 с перечнем полей и сообщений. Несуществующий id → 404,
нарушение уникальности/связей → 409. Дополнительно та же защита есть на уровне БД (`CHECK`, `UNIQUE`, `FK`).

## 7. Стартовые данные
При запуске `schema.sql` создает таблицы (если их нет), `data.sql` добавляет тестовые данные:
3 группы, 3 преподавателя, 4 предмета, 9 студентов, 29 оценок. Повторный запуск данные не дублирует
(`ON CONFLICT DO NOTHING`), счетчики id синхронизируются через `setval`.

## 8. Развертывание
- `Dockerfile` (multi-stage): на первом этапе Maven собирает `app.jar`, на втором в легкий образ JRE копируется только jar.
- `docker-compose.yml`: поднимает PostgreSQL (с healthcheck и volume для данных) и приложение;
  приложение стартует после готовности БД. Подключение настраивается переменными `DB_URL`, `DB_USER`, `DB_PASSWORD`.
- Запуск на сервере: `docker compose up --build -d`.

## 9. Возможные вопросы преподавателя
- **Почему DTO для запросов?** Чтобы клиент передавал только `groupId`/`teacherId`, а не целые вложенные объекты, и чтобы отделить правила валидации от модели БД.
- **Почему `schema.sql`, а не `ddl-auto`?** Структура БД под явным контролем (ограничения, индексы), как в реальных проектах.
- **Что такое JPA/ORM?** Библиотека, сопоставляющая Java-классы строкам таблиц; Hibernate - ее реализация.
